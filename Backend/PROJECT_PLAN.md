## 一、项目概述

### 1. 项目背景
目前学院小型图书室仍采用纸质笔记本登记借阅信息，存在图书查找慢、借阅记录易丢失、库存统计麻烦、逾期无法提醒等问题。作为第一次做信息系统项目的小组，我们选择开发一个轻量、基础、易实现的图书借阅管理系统，解决人工管理的核心痛点，同时完成课程实践要求。

### 2. 项目目标
- 实现管理员和普通读者两种基础角色的登录与权限区分
- 完成图书、读者、借阅记录 3 个核心模块的基础增删改查（CRUD）
- 支持图书按书名模糊查询、借阅状态自动更新
- 系统能正常运行、可演示，无致命 bug

### 3. 开发环境与条件
- 开发工具：IntelliJ IDEA（后端）、VS Code（前端）、DBeaver（数据库）
- 前端技术：Vue3 + Element Plus（课程推荐组件库，易上手）
- 后端技术：Spring Boot 3.2 + MyBatis（简化数据库操作）
- 数据库：MySQL 8.0（最常用、资料多）
- 版本控制：Git + Gitee（课程要求，提交记录作为评分依据）
- 运行环境：JDK 17、Node.js 20

## 二、需求分析

### 1. 目标用户与使用场景
- 管理员：图书室管理员，在办公电脑上使用，负责录入图书信息、管理读者账号、登记借阅和归还
- 普通读者：学院学生，在教室 / 宿舍通过浏览器使用，查询图书是否可借、查看自己的借阅记录

### 2. 核心功能清单
模块	具体功能
登录模块	账号密码登录、角色自动识别、退出登录
图书管理	新增图书、修改图书信息、删除图书、按书名查询图书
读者管理	新增读者、修改读者信息、删除读者、查询读者
借阅管理	登记图书借阅、登记图书归还、查看所有借阅记录

### 3. 非功能需求
- 性能要求：页面加载时间≤2 秒，简单查询响应≤1 秒
- 安全要求：不同角色只能看到自己权限内的页面，密码简单加密存储
- 兼容性要求：支持 Chrome、Edge 浏览器即可

## 三、技术路线

### 1. 总体架构
采用最基础的前后端分离三层架构，新人容易理解和实现：
- 前端层：负责页面展示和用户输入，通过 HTTP 请求调用后端接口
- 后端层：接收前端请求，处理简单业务逻辑，调用数据库
- 数据层：存储图书、读者、借阅记录等数据

### 2. 主要技术
- 前端：Vue3（组合式 API）、Element Plus（现成 UI 组件，不用自己写样式）、Axios（发送请求）
- 后端：Spring Boot（快速搭建项目）、MyBatis（写简单 SQL 操作数据库）
- 数据库：MySQL（关系型数据库，适合存储结构化数据）
- 工具：Git（版本控制）、DBeaver（数据库管理）

### 3. 数据设计初步考虑
主要实体：用户（管理员 / 读者）、图书、借阅记录
关键关系：
- 一个读者可以借阅多本图书
- 一本图书可以被多个读者借阅（不同时间）
- 一条借阅记录对应一个读者和一本图书
